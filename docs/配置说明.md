# 配置说明

本文说明 `config.example.yaml` 的主要字段。首次部署时复制模板为 `config.yaml`，再填写企业微信、模型和 Redis 等真实配置。

```bash
cp config.example.yaml config.yaml
```

`config.yaml` 通常包含密钥和内网地址，不建议提交到 GitHub。

## 顶层结构

- `wechat`：企业微信企业、应用、回调、代理和消息去重配置。
- `api_keys`：模型供应商 API Key。
- `models`：OpenAI-compatible 模型配置。
- `redis`：Redis / Redis Stack 连接配置。
- `deployment`：服务端口、域名和媒体访问地址。
- `agent`：sub-agent 通知、中间件等运行时配置。
- `logging`：日志输出配置。
- `scheduler`：内置定时任务配置。

## 企业微信应用

每个企业微信自建应用写在 `wechat.agents` 下，key 使用应用 ID 字符串：

```yaml
wechat:
  corp_id: "YOUR_CORP_ID"
  agents:
    "1000001":
      name: "Demo Agent"
      agent_id: 1000001
      corp_secret: "YOUR_CORP_SECRET"
      token: "YOUR_TOKEN"
      encoding_aes_key: "YOUR_ENCODING_AES_KEY"
      plugins:
        - demo_agent
        - sub_agent_demo
      fetch_user_info: false
      include_time_info: true
```

字段说明：

- `corp_id`：企业微信企业 ID。
- `corp_secret`：当前应用 Secret。
- `token`：企业微信回调 Token。
- `encoding_aes_key`：企业微信回调 EncodingAESKey。
- `plugins`：当前应用启用的 Agent 插件白名单。只有写在这里的插件才允许被当前应用作为主 Agent 或 sub-agent 使用。
- `fetch_user_info`：是否在处理消息前获取企业微信用户信息。
- `include_time_info`：是否向 Agent 注入当前时间上下文。

`demo_agent` 是示例 orchestrator，配置了 `sub_agents: [sub_agent_demo]`。如果 `sub_agent_demo` 没有写进当前应用 `plugins`，运行时会忽略该委托关系并写 warning。

`sub_agent_demo` 也可以作为独立 Agent 使用：

```yaml
wechat:
  agents:
    "1000003":
      name: "Sub Agent Demo"
      agent_id: 1000003
      plugins:
        - sub_agent_demo
```

项目内置示例 Agent 插件：

- `demo_agent`：演示插件加载、上下文、工具调用和 sub-agent 委托。
- `sub_agent_demo`：演示被委托调用，也可以独立作为普通 Agent 使用。
- `ai_schedule_manager`：自然语言创建、查询、删除和修改提醒。

## 模型配置

模型使用 `langchain-openai` 的 OpenAI-compatible 接口。API Key 建议统一放在 `api_keys`，再由 `models.<profile>.api_key_config` 引用。

```yaml
api_keys:
  dashscope: "YOUR_DASHSCOPE_API_KEY"

models:
  dashscope:
    model: "qwen3.6-flash"
    base_url: "https://dashscope.aliyuncs.com/compatible-mode/v1"
    api_key_config: "dashscope"
    api_key_env: "DASHSCOPE_API_KEY"
    temperature: 0.7
    max_tokens: 8192
```

Agent 插件可以在自己的 `agent_config.yaml` 中通过 `model_profile` 选择模型配置，也可以用 `max_tokens` 覆盖输出上限。

## Agent 运行时配置

`agent.sub_agent_notify` 控制 orchestrator 调用 sub-agent 处理较慢时是否先发一条进度提示：

```yaml
agent:
  sub_agent_notify:
    enabled: true
    delay_seconds: 1.2
    template: "我让{agent_name}处理一下，稍等。"
```

`agent.middleware.summarization` 用于长对话压缩。当前 LangChain 版本支持 `SummarizationMiddleware` 时会启用；如果依赖版本不支持，运行时会跳过并写 warning。

## Redis

Redis 是必需依赖，用于：

- LangGraph checkpoint / 短期记忆。
- APScheduler jobstore 和 leader lock。
- 企业微信 token、消息去重和提醒任务等业务数据。

LangGraph Redis checkpoint 需要 Redis Stack 能力，建议使用 `docker-compose.yml` 中的 `redis-stack` 服务。

```yaml
redis:
  host: "redis-stack"
  port: 6379
  password: null
  db: 0
```

如果 Redis 连接失败，或 Redis checkpoint 初始化失败，程序会直接退出。`db` 建议保持为 `0`。

## 定时任务

项目内置示例定时任务：

- `morning`：早安消息。
- `today_60s`：每日 60 秒图片消息。

```yaml
scheduler:
  test: false
  tasks:
    morning:
      time: "08:30"
      day_of_week: "*"
      users:
        - "user1"

    today_60s:
      time: "09:50"
      day_of_week: "*"
      users:
        - "user1"
```

用户通过 `ai_schedule_manager` 创建的提醒不写在这里，会由工具写入 Redis 并注册到 APScheduler。

## 回调与健康检查

启动服务后：

- 健康检查：`GET /health`
- 企业微信接收消息：`https://your-domain.com/<agent_id>/wechat`

Docker 默认启动命令：

```bash
uvicorn app.main:app --host 0.0.0.0 --port 4455
```
