# Agent 插件与任务开发

wxbot 当前使用 `app/` 包作为运行时代码目录。对话能力通过 `app/agent_plugins/` 下的 Agent 插件扩展，定时任务通过 `app/tasks/` 注册。

## 插件结构

每个 Agent 插件是一个独立目录：

```text
app/agent_plugins/demo_agent/
  __init__.py
  agent_config.yaml
  tools.py
  logic.py
```

项目内置示例插件：

- `demo_agent`
- `sub_agent_demo`
- `ai_schedule_manager`

## agent_config.yaml

示例：

```yaml
key: demo_agent
name: Demo Agent
display_name: Demo Agent
description: 演示 wxbot 的插件加载、工具调用、路由、上下文和 sub-agent 委托能力
status: enable
category: chat
model_profile: dashscope
model: qwen3.6-flash
temperature: 0.3
max_tokens: 2048
route_keywords:
  - demo
custom_tools:
  - demo_system_status
  - demo_list_agent_plugins
global_tools:
  - time_query
  - help_text
sub_agents:
  - sub_agent_demo
system_prompt: |
  你是 wxbot 的 Demo Agent。
```

字段说明：

- `key`：插件唯一标识，通常与目录名一致。
- `status`：`enable` / `disable`。
- `category`：插件分类；带 `sub_agents` 的 `category: chat` 插件会优先作为 orchestrator。
- `model_profile`：引用 `config.yaml` 中的 `models.<profile>`。
- `route_keywords`：没有 orchestrator 时的关键词路由。
- `custom_tools`：当前插件 `tools.py` 里允许暴露给模型的工具。
- `global_tools`：共享工具，例如 `time_query`、`help_text`。
- `sub_agents`：当前 Agent 可以委托的其他 Agent。
- `system_prompt`：Agent 系统提示词。

## Orchestrator 与 sub-agent

`demo_agent` 是 orchestrator，配置了：

```yaml
sub_agents:
  - sub_agent_demo
```

运行时会为它生成 `call_agent_sub_agent_demo` 工具。模型判断用户请求需要子 Agent 处理时，会调用该工具。

`sub_agent_demo` 也可以独立作为普通 Agent 使用：

```yaml
wechat:
  agents:
    "1000003":
      plugins:
        - sub_agent_demo
```

某个 sub-agent 只有同时满足以下条件才会生成委托工具：

- 插件存在且 `status: enable`
- 写在当前企业微信应用的 `plugins` 中
- 写在 orchestrator 的 `sub_agents` 中

如果 `sub_agents` 中有 `aaaa`，但 `aaaa` 没有写入当前应用 `plugins`，Runtime 会忽略它并记录 warning；如果插件不存在或被禁用，也同样不会生成 `call_agent_aaaa`。

## 自定义工具

`tools.py` 需要实现 `build_tools`：

```python
def build_tools(*, agent_id: str, user_id: str, enabled_tools: list[str]):
    from langchain_core.tools import tool

    @tool
    def demo_echo(text: str) -> str:
        """回显用户输入，用于验证工具调用链路。"""
        return f"echo: {text}"

    all_tools = [demo_echo]
    return [item for item in all_tools if item.name in enabled_tools]
```

工具只在 Agent 被选中后可用。是否调用工具、调用哪个工具，由 LangChain Agent 根据用户输入和 `system_prompt` 决定。

项目内置共享工具：

- `app/tools/basic.py`
- `app/tools/schedule.py`
- `app/tools/wecom.py`

## 路由逻辑

如果当前企业微信应用启用了带 `sub_agents` 的 `category: chat` 插件，Runtime 会优先选择它作为 orchestrator，由它决定是否调用 sub-agent。

没有 orchestrator 时，默认路由使用 `route_keywords`。当一个企业微信应用启用多个普通插件时，Runtime 会先计算关键词命中分数，再把消息交给得分最高的 Agent。

需要更复杂的规则时，可以在 `logic.py` 中实现：

```python
def route_score(message_text: str, profile) -> int:
    if "demo" in message_text:
        return 10
    return 0
```

流程可以理解为：

```text
企业微信消息 -> Runtime 选择 Agent/orchestrator -> Agent 决定是否调用工具或 sub-agent -> 返回企业微信消息
```

## 启用插件

在 `config.yaml` 的目标企业微信应用下配置：

```yaml
wechat:
  agents:
    "1000001":
      plugins:
        - demo_agent
        - sub_agent_demo
```

`plugins` 表示当前企业微信应用启用哪些 Agent 插件；工具绑定不写在这里，而是写在插件自己的 `agent_config.yaml`。

## 自定义定时任务

任务文件放在 `app/tasks/`，使用 `app.scheduler.task_registry.scheduled_task` 注册。

```python
from typing import List

from app.scheduler.task_registry import scheduled_task


@scheduled_task(key="daily_ping", mode="batch", default_time="09:00")
def send_daily_ping(user_ids: List[str]):
    for user_id in user_ids:
        print(f"send message to {user_id}")
```

项目内置示例任务：

- `app/tasks/morning_job.py`
- `app/tasks/today_60s.py`
